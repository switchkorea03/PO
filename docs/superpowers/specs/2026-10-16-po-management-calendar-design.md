# PO 관리·업무 달력·문자 알림 설계명세서

- 작성일: 2026-10-16
- 상태: 설계 검증 및 사용자 협의 반영본
- 원본: `2026-10-15-po-management-calendar-design.md`
- 목적: 국내·해외 PO를 관리하고, 날짜별 업무를 달력과 휴대폰 문자로 안내한다.
- 적용 우선순위: 이번 범위에서는 이 문서가 2026-10-12·13 설계·실행계획 및 2026-10-15 설계보다 우선한다. 기존 실행계획을 그대로 실행하지 않는다.

## 1. 범위와 기본 원칙

사내 업무담당자가 PO 파일을 업로드하면 시스템이 정보를 추출한다. 담당자가 인식 결과를 확인·수정하여 등록하면 국내 출고일, 해외 PO 수령일 및 ETD를 기준으로 업무를 생성한다. 담당자는 달력에서 업무를 확인하고 기존 도구로 실제 업무를 수행한 뒤 완료 체크한다.

이번 기능 범위는 PO 업로드, 정보 추출·수정, PO 목록·상세, 분할출고·잔량 관리, 업무 달력, 세부 작업 완료 처리, 휴대폰 문자 알림이다.

ERP 등록, 메일 발송, 문서 작성·인쇄·전달, 출하계획 Excel 입력은 담당자가 직접 수행한다. 시스템은 이러한 업무를 실행하지 않는다. 인보이스 작성·번호·파일·PO 연결도 시스템에서 관리하지 않으며, `인보이스+ERP` 업무만 안내한다.

이 문서에서 **사내 업무담당자**는 시스템에서 PO와 업무를 처리하는 사용자이며, **고객 담당자**는 발주한 고객사의 연락 담당자다. 초기 문자 수신자는 사용자 본인 한 명이다.

## 2. 파일 업로드와 정보 추출

- 지원 파일: PDF, Excel(.xlsx, .xls).
- PDF는 문자 또는 스캔 이미지를 인식하고, Excel은 셀 데이터를 우선 읽는다.
- 판독 불가·누락·불일치는 원인을 표시하고 직접 입력·수정할 수 있게 한다.
- 필수값을 추측하여 확정하지 않는다. 등록 전 담당자가 확인한다.
- 파일명과 문서 안의 문장은 시스템 실행 지시로 취급하지 않는다.
- 외부 OCR 서비스는 회사 승인 전에는 사용하지 않는다. 구체적인 인식 엔진은 구현 시 선정한다.

## 3. PO 정보 관리

### 3.1 공통 정보

- 국내·해외 구분
- 고객사명·고객 담당자
- PO 번호·주문일·수령일
- 품목코드·품명 또는 모델명
- 품목별 주문수량·단위
- 품목별 단가·통화·공급가액
- 품목별 원문 요청납기
- 비고
- 원본 파일·버전·인식 및 수정 이력

한 PO에 여러 품목이 있으면 품목별 행으로 관리한다. 공급가액은 수량 × 단가로 계산하며 원문과 다르면 확인 표시한다. 금액의 소수점 정밀도를 보존하고 단위를 임의 환산하지 않는다.

국내·해외 기본값은 고객사 설정을 사용하되 등록 시 수정할 수 있다. 통화는 국내·해외 구분과 별개로 관리한다. 국내 USD 거래에는 국내 일정과 수출 ERP 메뉴 안내를 적용한다.

### 3.2 국내 납기·출고일

국내 PO는 품목별 요청납기를 기준으로 한다. 같은 고객·같은 PO 안에서 납기가 같은 품목들을 첫 출고회차로 묶는다. 고객이나 PO가 다르면 납기가 같아도 출고회차를 합치지 않는다.

첫 출고일은 해당 품목의 납기에서 제안하고 담당자가 수정할 수 있다. 국내 실제 출고는 평일을 전제로 한다. 원문 납기와 수정한 출고일을 각각 보존한다.

국내 납기 미정을 정상 운영 시나리오로 가정하지 않는다. 인식하지 못한 요청납기는 원본을 확인하여 입력한다.

### 3.3 해외 수령일·ETD·ETA

- PO 수령일은 반드시 확인한다. 업로드일을 제안하되 실제 수령일로 수정할 수 있다.
- 해외 PO 원문 요청납기는 고객이 임의로 작성할 수 있으므로 일정 계산과 달력 납기 표시에서 제외한다. 원문 정보로만 보존한다.
- ETD는 PO 수령 시 미정일 수 있으며 담당자가 추후 입력·수정한다.
- ETD는 주말일 수도 있으며 입력값을 그대로 보존한다.
- ETA는 고객 안내를 위해 필요 시 직접 기록하며 ERP 후속업무 날짜 계산에 사용하지 않는다.
- 인보이스 정보는 관리하지 않는다.

### 3.4 출고·선적회차와 수량

일반적으로 한 번의 출고를 기본으로 하되 국내·해외 모두 회차를 추가할 수 있다. 회차에는 대상 품목·수량과 국내 출고일 또는 해외 ETD·ETA를 기록한다.

예정수량과 실제수량을 별도 입력칸으로 나누지 않는다. **회차별 수량을 한 번 입력하고, 회차의 `출고 완료` 처리 시 해당 수량을 출고실적으로 확정한다.** 해외에도 같은 원칙을 적용한다.

예를 들어 주문 100개를 1차 70개·2차 30개로 등록하고 1차만 출고 완료하면 누적 출고수량은 70개, PO 잔량은 30개다. 두 회차를 등록했다는 이유만으로 잔량을 0으로 처리하지 않는다.

- 품목별 회차 배정 합계가 주문수량을 초과하지 않도록 검증한다.
- 누적 출고수량은 출고 완료된 회차의 수량 합계로 계산한다.
- 취소가 없는 경우 잔량은 주문수량에서 누적 출고수량을 뺀 값이다.
- 잔량 취소가 있는 경우 취소수량도 구분하여 남은 출고 대상 수량을 계산한다.
- 달력 업무 완료와 회차 출고 완료는 별개다. 업무 체크만으로 출고실적을 확정하지 않는다.
- 출고 완료 실적의 오류는 변경 이력을 남기는 정정으로 처리한다.

### 3.5 중복·수정본·취소

같은 파일을 다시 업로드하면 기존 PO를 안내해 중복 등록을 방지한다. 같은 고객·PO 번호의 다른 파일은 수정본 후보로 표시하고 담당자가 비교하여 반영한다. 원본·버전·변경 이력을 보존한다.

주문수량을 이미 출고한 수량보다 작게 수정하는 것은 막는다. 미출고 잔량은 별도로 취소하고 출고실적은 보존한다. 실적 자체가 잘못된 경우 정정 절차를 사용한다.

PO 전체 취소 시 미완료 업무는 취소하고 완료 기록은 유지한다. 부분 취소 시 해당 물량에 연결된 미완료 업무를 검토하여 취소·조정한다.

## 4. 업무 달력

월간 보기를 기본으로 하고 주간 보기와 선택 날짜의 업무 목록을 제공한다. 국내·해외 및 고객별로 필터링한다.

각 업무는 미완료·완료·취소 상태를 가지며 지난 날짜의 미완료 업무는 지연 표시한다. 복합 업무는 일부 세부 작업만 끝났을 때 부분완료로 표시하되 미완료 업무로 취급한다.

달력에는 확정된 짧은 문구를 표시한다. 상세에서는 고객명, PO 번호, 회차, 품목·수량, 원래 기준일, 자동 계산일, 최종 업무일, 세부 작업과 완료 체크를 보여준다. 고객을 식별할 수 있게 표시하며 긴 문구는 말줄임 처리한다.

같은 날짜의 국내 출고 내역 공유는 고객명 중복을 제거하여 `A,B(출고 내역 공유)`로 묶는다. 묶음 안의 고객·PO·회차별 업무와 완료 상태는 개별 유지한다. 다른 동일 업무 문구도 날짜별로 묶어 건수를 표시할 수 있다.

국내 납기는 `고객사명(납기)`로 표시하고 해당 품목을 상세에서 확인한다. 납기는 완료 체크 대상이 아니다. 출고일과 납기가 같아도 원문 납기정보를 보존한다. 해외 원문 납기는 달력에 표시하지 않는다.

**모든 업무는 다른 업무일로 직접 이동·수정할 수 있다.** 수동 지정 표시를 남기고 자동 재계산으로 덮어쓰지 않는다. 사내 업무일은 평일 운영을 기준으로 하며 공휴일·회사휴무일은 담당자가 직접 조정한다.

## 5. 국내 일정

아래 업무는 출고회차별로 생성한다.

| 시점 | 달력 문구 | 상세 업무 |
|---|---|---|
| 출고 전날 준비일 | 고객사명(출고 내역 공유) | 출고품·수량·출고일을 고객에게 메일로 전달한다. |
| 출고 전날 준비일 | 의뢰서(ERP)+명세서(PDF) 전달 | 거래명세서를 PDF로 저장·인쇄하고, ERP 출고의뢰를 등록·인쇄하여 구매팀에 함께 전달한다. |
| 출고 당일 | 명세서 공유 | 거래명세서 PDF를 고객에게 전달한다. |
| 출고 당일 | 엑셀 기입 | 출하계획 Excel에 수량을 직접 입력한다. |
| 출고 당일 | 전표 인쇄 | ERP 출고전표를 인쇄하고 반으로 잘라 지정 바구니에 전달한다. |

출고 전날 준비일은 실제 출고일 이전의 가장 가까운 평일이다. 월요일 출고라면 직전 금요일이다.

| 거래 구분 | 출고의뢰 등록·인쇄 | 출고전표 인쇄 |
|---|---|---|
| 국내 KRW | 출고의뢰등록 | 출고처리 |
| 국내 USD 및 해당 수출거래 | 출고의뢰등록(수출) | 거래명세서(수출) |

국내 KRW·USD 외 통화는 ERP 메뉴를 임의 선택하지 않고 담당자가 거래유형을 지정한다. 해외 중계무역에는 국내 출고 업무 전체를 추가하지 않는다.

## 6. 해외 일정

| 기준일 | 달력 문구 | 상세 업무 |
|---|---|---|
| PO 수령 당일 | 인보이스+ERP | 인보이스를 작성하여 중국 공장에 메일로 전달하고 ERP 주문등록(수출)에 등록한다. |
| PO 수령일 기준 차주 화요일 | BL, ETA 고객 공유 | BL 서류와 ETA를 고객에게 메일로 전달한다. |
| ETD 다음 날 | ERP 2개 처리 | 수입선적등록(수입), 입고처리(수입)를 처리한다. |
| ETD 다음 날 | 출고 메일 | 중계무역 출고메일을 내부 영업관리팀에 공유한다. |
| ETD 다음 날 | 엑셀 기입 | 출하계획 Excel에 수량을 직접 입력한다. |

`인보이스+ERP`와 `BL, ETA 고객 공유`는 PO별로 생성한다. 인보이스를 여러 PO에 걸쳐 작성하는 업무는 담당자가 시스템 밖에서 관리한다.

`차주 화요일`은 원래 PO 수령일이 속한 주의 다음 주 화요일이다. 주는 월요일~일요일이다. 중국 공장의 주간 선적 운영을 반영한 규칙이며, 수령일을 주말 보정한 날짜로 바꾸어 계산하지 않는다. 필요하면 담당자가 해당 업무를 다른 날짜로 옮길 수 있다.

ETD 후속업무는 선적회차별로 생성한다. ETD 미정이면 PO 상세에 날짜 미정 업무로 표시하고 달력과 문자 대상에서 제외한다. ETD 입력 시 일정을 배치한다.

ETD를 다시 지우면 미완료 후속업무를 날짜 미정으로 돌린다. 수동 지정 업무도 재확인 필요를 표시하고 ETD가 다시 정해지기 전까지 문자 발송을 보류한다. 완료 기록은 유지한다.

BL 파일 업로드·자동판독은 필요하지 않다. ERP·내부메일·Excel 업무의 날짜 기준은 ETA가 아니라 ETD다.

## 7. 날짜 계산과 변경

한국시간(Asia/Seoul)의 날짜를 사용한다. 토요일·일요일만 자동 보정하며 법정공휴일과 회사휴무일은 자동 계산에 포함하지 않는다.

1. 원문 납기, 실제 PO 수령일, 입력 ETD는 변경 없이 보존한다.
2. 국내 기본 출고일이 주말이면 다음 월요일로 제안하고 실제 평일 출고일로 수정할 수 있다.
3. 국내 준비업무는 출고일 이전의 가장 가까운 평일에 배치한다.
4. 국내 당일 업무는 확정한 출고일에 배치한다.
5. 해외 수령 당일 업무는 수령일이 주말이면 다음 월요일에 배치한다.
6. 해외 차주 화요일은 원래 수령일이 속한 주를 기준으로 계산한다.
7. ETD 후속업무는 원래 ETD에 1일을 더하고 결과가 주말이면 다음 월요일로 옮긴다.
8. 국내 납기 표시는 주말이면 다음 월요일에 배치하되 원문 납기를 상세에 보여준다.
9. 수동으로 옮긴 업무는 지정한 최종 업무일을 사용한다.

| 조건 | 계산 결과 |
|---|---|
| 국내 출고일 2026-10-19 월요일 | 준비업무 10-16 금요일, 당일 업무 10-19 |
| ETD 2026-10-15 목요일 | 후속업무 10-16 금요일 |
| ETD 2026-10-16 금요일 | 후속업무 10-19 월요일 |
| ETD 2026-10-17 토요일 | 후속업무 10-19 월요일 |
| ETD 2026-10-18 일요일 | 후속업무 10-19 월요일 |
| PO 수령일 2026-10-18 일요일 | 접수업무 10-19 월요일, BL·ETA 공유 10-20 화요일 |

### 기준일 변경·재확인·중복 방지

- 출고일·수령일·ETD 변경 시 연결된 미완료 자동 일정을 재배치한다.
- 수동 지정 업무일은 덮어쓰지 않고 재계산 필요를 표시한다. 자동일정으로 되돌릴 수 있다.
- 완료 업무의 기존 날짜·완료일·이력은 보존한다.
- 출고일·수량 등 관련 정보가 바뀌면 영향을 받는 완료 업무에 `변경 후 재확인 필요`를 표시한다. 담당자가 재작업 여부를 결정한다.
- 재확인 표시 자체만으로 완료 업무를 미완료로 바꾸거나 반복 문자 대상에 넣지 않는다. 재작업이 필요하여 미완료로 전환한 경우 해당 업무일의 알림 규칙을 적용한다.
- PO·회차·업무종류별 식별자를 유지하여 재저장으로 중복 생성하지 않는다. PO 단위 업무는 회차 없이 식별한다.
- 과거 PO를 등록하면 계산된 과거 업무일을 유지하며 미완료 업무는 지연 표시한다.

## 8. 세부 작업과 완료 처리

복합 업무에는 세부 체크를 제공하며 모두 체크해야 업무가 완료된다. 일부만 완료하면 부분완료로 표시하고 남은 작업을 문자에 안내한다.

예시:

- `인보이스+ERP`: 인보이스 작성·중국 공장 전달 / ERP 주문등록(수출).
- `ERP 2개 처리`: 수입선적등록(수입) / 입고처리(수입).
- `의뢰서(ERP)+명세서(PDF) 전달`: 명세서 PDF 저장·인쇄 / 출고의뢰 등록·인쇄 / 구매팀 전달.
- `BL, ETA 고객 공유`: BL 전달 / ETA 안내.

완료자와 완료시각을 기록한다. 업무 완료와 출고실적 확정은 별도로 유지한다.

## 9. 휴대폰 문자 알림

### 9.1 목적과 수신자

사용자가 업무를 잊지 않도록 휴대폰 문자로 알린다. 고객에게 발송하지 않는다. 초기 수신자는 사용자 본인 한 명이며 설정에서 전화번호를 등록·변경한다.

문자 발송 서비스는 시스템 기능 범위에 포함하되, 서비스 선정·발신번호 등록·인증정보 설정은 구현·운영 준비 단계에서 진행한다. PO 인보이스 메일이나 고객 안내메일 발송을 자동화하는 기능은 아니다.

### 9.2 정기 알림

- 한국시간 기준 **평일 오전 9시**에 발송한다.
- **오늘 해야 할 미완료 업무와 이전 날짜의 미완료·부분완료 업무**를 묶는다.
- 오늘 업무와 지연 업무를 구분한다.
- 고객명과 업무 종류를 표시하고 복합 업무는 남은 세부 작업을 안내한다.
- 완료·취소·날짜 미정 업무와 완료 체크 대상이 아닌 납기 표시는 제외한다.
- 발송할 업무가 없으면 보내지 않는다.
- 내용이 길면 장문문자로 발송한다.

예시:

> 오늘: A사 출고 준비 — 출고 내역 공유, 구매팀 전달. B사 인보이스+ERP — ERP 등록 미완료. 지연: C사 ERP 2개 처리 — 입고처리 미완료. 상세는 업무 달력에서 확인하세요.

### 9.3 달력과의 날짜 일치

문자는 원래 기준일이 아니라 **달력에 최종 배치된 업무일**을 따른다.

- 월요일 출고 준비업무가 금요일에 있으면 금요일 오전 9시에 알린다.
- 금요일·토요일·일요일 ETD의 후속업무가 월요일에 있으면 월요일 오전 9시에 알린다.
- BL·ETA 공유를 화요일에서 수요일로 옮기면 수요일에 알린다.
- 미완료 업무가 지난 날짜에 남아 있으면 이후 평일 정기 문자에 계속 포함한다.

### 9.4 당일 추가 알림과 중복 방지

오전 정기 발송 후 PO 등록·ETD 입력·업무일 이동 등으로 당일 업무가 새로 생기면, 저장을 확정할 때 추가된 업무만 별도 문자로 알린다.

업무 식별자와 발송 기록을 사용해 단순 재저장으로 중복 발송하지 않는다. 정상적인 다음 평일의 지연 업무 재안내는 중복 오류로 보지 않는다. 발송 직전에도 현재 완료·취소·날짜 상태를 확인한다.

### 9.5 실패 처리

- 서비스에서 명확한 발송 실패가 반환되면 5분 간격으로 최대 3회 재시도한다.
- 발송 결과가 불명확하면 서비스의 발송 내역을 먼저 확인하여 중복 발송을 방지한다.
- 최종 실패는 달력 화면에서 확인할 수 있게 표시한다.
- 최초 요청·재시도·서비스 응답·최종 결과를 발송 이력에 남긴다.

## 10. 화면 구성

1. **PO 업로드·확인:** 원본·추출값 비교, 누락·불일치 표시, 국내외 구분 및 날짜 확인.
2. **PO 목록:** 고객·PO 번호·품목 검색, 국내외·진행상태·잔량 필터.
3. **PO 상세:** 원본·버전, 품목·금액·납기, 회차·수량·출고 완료, ETD·ETA, 잔량·취소, 업무·세부 체크, 변경 이력.
4. **업무 달력:** 월간·주간·날짜별 목록, 고객 필터, 묶음 표시, 업무일 이동, 미완료·부분완료·지연·재확인 및 문자 실패 표시.
5. **설정:** 사용자·권한 관리, 문자 수신번호, 발송 서비스 설정 및 발송 이력.

## 11. 데이터 구성

- **고객:** 고객명·담당자, 국내외 기본값, 거래통화.
- **PO:** 고객, 번호, 주문일·수령일, 국내외 구분, 원본·버전, 진행상태.
- **PO 품목:** 코드·명칭, 주문수량·단위·단가·통화·공급가액, 원문 요청납기, 취소수량.
- **출고·선적회차:** PO·품목 연결, 회차별 수량, 국내 출고일 또는 해외 ETD·ETA, 출고 완료 상태·처리자·처리시각.
- **업무:** PO 및 해당 시 회차 연결, 종류·문구, 기준일·자동 계산일·수동 지정일·최종 업무일, 상태·완료일, 재확인 표시.
- **세부 작업:** 상위 업무, 작업 종류·내용, 완료 여부·완료자·완료시각.
- **변경 이력:** 변경 대상·변경자·변경시각·이전 값·새 값.
- **문자 설정·발송 이력:** 수신번호, 대상 업무, 발송 종류·예정시각·요청시각, 중복 방지 식별정보, 서비스 발송 식별자, 결과·재시도·실패 사유.
- **사용자:** 계정·권한·활성 상태.

파일 인식, PO 관리, 일정 계산, 달력 표시, 문자 발송을 별도 구성요소로 둔다. 날짜 규칙을 바꿀 때 파일 인식 부분까지 수정할 필요가 없도록 한다.

## 12. 권한·보관·운영

회사 내부 웹 화면에서 사용한다. 관리자는 계정과 권한을 관리하고 등록된 업무담당자는 모든 PO를 공동 조회·수정한다. 계정이 없는 사용자는 원본·PO·업무·전화번호를 조회할 수 없다.

변경자와 완료자를 기록한다. 동시 수정 시 다른 사용자의 변경을 조용히 덮어쓰지 않고 충돌을 안내한다. 원본 파일과 데이터를 함께 백업한다.

외부 OCR은 회사 승인 전 사용하지 않는다. Outlook·ERP 계정 연결, 회사 공유 Excel 경로 설정, 외부 캘린더 동기화, 메일·푸시 알림은 이번 범위에 포함하지 않는다. 휴대폰 문자는 별도 필수 기능이다.

## 13. 인수 기준

### PO·수량

- PDF·Excel을 업로드하고 추출값을 확인·수정할 수 있다.
- 인식 실패 시 직접 입력할 수 있고 필수값을 추측하지 않는다.
- 같은 파일의 재등록과 같은 고객·PO 번호의 수정본 후보를 구분한다.
- 국내 동일 고객·PO 안의 같은 납기 품목은 첫 출고회차로 묶고, 다른 고객·PO는 별도로 유지한다.
- 회차별 수량을 한 번 입력하며 출고 완료 전에는 출고실적으로 계산하지 않는다.
- 100개 주문에서 70개 회차만 출고 완료하면 누적 출고 70개·잔량 30개로 표시한다.
- 회차 배정 초과와 출고실적보다 작은 주문수량 변경을 막는다.
- 잔량 취소와 출고실적 정정 이력을 보존한다.

### 일정·완료

- 국내 출고일을 수정하면 연결된 미완료 자동 업무가 재배치된다.
- 월요일 출고 준비업무가 금요일에 표시된다.
- 고객명을 식별할 수 있고 같은 날의 출고 내역 공유를 묶되 개별 상태를 유지한다.
- 국내 KRW·USD에 맞는 ERP 메뉴를 안내한다.
- 해외 PDF 요청납기는 일정과 달력 납기 표시에서 제외한다.
- 해외 수령 당일에 `인보이스+ERP`, 원래 수령일 기준 차주 화요일에 `BL, ETA 고객 공유`를 생성한다.
- 인보이스 정보·파일·PO 연결 기능을 요구하지 않는다.
- ETD 미정 업무는 달력과 문자에서 제외하고 입력 시 배치한다.
- 금·토·일 ETD의 후속업무가 월요일에 표시된다.
- ETD를 지우면 미완료 후속업무의 배치·문자를 보류하고 완료 이력은 보존한다.
- 업무일을 직접 옮길 수 있고 재계산이 수동 지정일을 덮어쓰지 않는다.
- 기준정보 변경 시 관련 완료 업무에 재확인 필요를 표시한다.
- 복합 업무는 세부 체크를 모두 완료해야 완료 상태가 된다.
- 재저장으로 업무가 중복 생성되지 않는다.

### 문자·운영

- 평일 오전 9시에 오늘 업무와 이전 미완료 업무를 사용자 본인에게 발송한다.
- 완료·취소·날짜 미정 업무와 납기 표시는 문자에서 제외한다.
- 문자일이 달력의 최종 업무일과 일치한다.
- 월요일 출고의 준비업무를 금요일 오전 9시에 알린다.
- 정기 발송 이후 생긴 당일 업무는 추가 알림으로 보내고 단순 재저장은 중복 발송하지 않는다.
- 부분완료 업무는 남은 세부 작업을 안내한다.
- 명확한 실패는 5분 간격으로 최대 3회 재시도하고 결과 불명확 시 발송 내역부터 확인한다.
- 최종 실패 표시와 발송 이력을 확인할 수 있다.
- 등록 사용자만 접근하며 변경자·완료자를 기록하고 동시 수정 충돌을 안내한다.
- ERP·메일·Excel 실제 작업은 자동 실행하지 않는다.

## 14. 구현 준비 시 확정할 운영 설정

아래는 이번 설계에서 기능 원칙을 정했으나 실제 값·제품을 지정하지 않은 항목이다.

- 문자 서비스 공급자·발신번호·인증정보·사용자 수신번호.
- 회사 내부 배포 위치·접속 방식·초기 사용자 계정.
- 승인 범위 내 PDF·스캔·Excel 인식 구성과 실제 PO 샘플을 이용한 인식 검증.
- 백업 위치·주기·복구 절차.

본 문서는 설계 합의 반영본이며 구현 완료나 실제 문자 발송 설정 완료를 뜻하지 않는다. 새 실행계획은 이 범위를 기준으로 작성한다.
