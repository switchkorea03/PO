# PO 발주·출고 업무 자동화 설계명세서

- 작성일: 2026-10-12
- 문서 상태: 사용자 검토본
- 대상 독자: 영업·구매·영업관리 현업 담당자, 시스템 개발·운영 담당자
- 기준 시스템: 더존 iCUBE, Microsoft 365 Outlook, 회사 공유폴더 월별 Excel

## 1. 목적

고객 PO 접수부터 재고 확인, 생산요청, 국내 출고, 해외 중계무역 선적, 문서와 메일 처리, 실제 수량 반영까지의 업무를 하나의 내부 웹 시스템에서 관리한다. 정상 건은 가능한 범위에서 자동 처리하고, 생산요청 수량 결정, 중요 ERP 등록, 수량·날짜 불일치, 공유 Excel 반영은 담당자가 확인하거나 승인하도록 한다.

시스템은 다음 결과를 달성해야 한다.

- 고객별로 다른 PO PDF와 Excel 양식을 일관된 주문 데이터로 관리한다.
- PO 원본, iCUBE 처리, Outlook 메일, 출고·선적 문서와 공유 Excel 반영 이력을 하나의 업무 건으로 연결한다.
- 국내 분할납품의 회차별 수량과 잔량을 정확히 관리한다.
- 해외 QY Invoice와 중국 공장의 QP·BL을 자동으로 연결하고 ETD·ETA·실제 선적수량을 검증한다.
- 잘못된 생산요청, 중복 메일, 중복 ERP 등록, 잘못된 Excel 셀 입력을 방지한다.

## 2. 범위

### 2.1 포함 범위

- 내부 웹사이트를 통한 PO PDF 업로드와 주문 관리
- 고객별 PO 형식 인식 및 필수정보 추출
- 공통 주문 데이터 저장 및 고객별 Excel 생성
- 국내·해외 주문 구분
- 더존 iCUBE 재고·발주·수입·출고 업무 연계
- 생산요청 초안, 담당자 입력·승인 및 ERP 등록
- 국내 일반납품과 특정 고객의 분할납품 관리
- 국내 거래명세서·출고의뢰서·출고전표 업무 지원
- 해외 QY Invoice 생성·발송과 QP·BL 자동 수신·검증
- Microsoft 365 Outlook 메일 발송·수신과 실패 알림
- 회사 공유폴더 월별 Excel의 실제 수량 반영
- 예외 작업함, 승인, 감사이력, 재처리

### 2.2 제외 범위

- FCST와 안전재고 배수를 이용한 생산요청 수량 자동 결정
- 영업담당자 간 미확정 출고계획을 이용한 가용재고 자동 배분
- 중국 공장 실제 물리재고의 상시 자동 조회
- 종이문서의 물리적 전달과 지정 바구니 보관 자체의 자동화
- 3개월 후 도입 가능성이 있으나 제품이 정해지지 않은 차기 ERP에 대한 연계 개발

향후 모든 영업담당자가 시스템을 사용하면 담당자 간 예약재고와 출고계획을 통합해 가용재고를 자동 계산하는 기능을 별도 단계로 확장할 수 있다.

## 3. 설계 원칙

1. **시스템이 기준 원본이다.** PO와 업무상태는 웹 시스템의 데이터베이스에서 관리하고 Excel은 입출력 결과물로 사용한다.
2. **정상 건은 자동, 판단이 필요한 건은 승인 후 처리한다.** 문서 변환, 메일 수집, 번호 연결과 단순 검증은 자동화하되 생산수량과 중요 불일치는 사람이 결정한다.
3. **외부 시스템 실패는 중복을 만들지 않아야 한다.** 모든 ERP·메일·Excel 작업에 업무 건 식별자와 처리 상태를 두고 재시도 시 같은 작업이 다시 등록되지 않게 한다.
4. **고객별 차이는 기준정보로 관리한다.** PO 양식, 고객사 코드, Excel 양식, 분할납품 허용 여부, 메일 수신자 등을 프로그램 수정 없이 변경할 수 있게 한다.
5. **원본과 변경 이력을 보존한다.** 원본 문서, 자동 추출값, 사용자의 수정값, 승인자와 외부 시스템 결과를 감사이력으로 남긴다.

## 5. 시스템 구성

### 5.1 내부 웹 애플리케이션

회사 계정으로만 로그인할 수 있는 내부 업무 사이트다. PO 업로드, 주문 조회, 승인, 예외 처리와 기준정보 관리를 제공한다. 외부 공개 사이트로 운영하지 않는다.

### 5.2 문서 처리 모듈

- 고객별 PO PDF 분류와 필드 추출
- 필수값 및 공급가액 검증
- 고객별 Excel, QY Invoice, 거래명세서와 출고 관련 문서 생성
- BL Excel의 `BL` 시트 내 이미지에서 `ON BOARD` 날짜 인식
- 원본과 생성 문서의 버전 및 연결관계 관리

### 5.3 iCUBE 연계 모듈

- 국내: `일별재고현황` 조회
- 해외: `발주미납현황(수입)` 조회
- 국내·해외 생산요청: `발주등록(수입_기타)` 등록
- 해외 후속업무: 수입선적등록과 입고처리
- 국내 후속업무: 기존 주문등록, 출고의뢰서와 출고전표 업무 지원

iCUBE의 실제 연계 방식은 회사의 버전, 라이선스와 권한을 확인해 다음 순서로 선택한다.

1. 더존이 제공하고 회사가 사용할 수 있는 공식 연계 인터페이스
2. 회사와 더존이 승인한 DB·파일 연계
3. 앞 방식이 불가능할 때 승인된 화면 자동화

연계 방식과 무관하게 웹 시스템은 동일한 내부 인터페이스를 사용해 업무 로직과 iCUBE 연결 코드를 분리한다.

### 5.4 Outlook 연계 모듈

Microsoft 365 권한을 사용해 지정 메일함을 감시하고 메일·첨부파일을 수집한다. 중국 공장 발신자는 여러 명을 등록할 수 있고 관리자가 추가·변경·비활성화할 수 있다. 등록되지 않은 발신자의 BL 메일은 자동 반영하지 않고 예외로 보낸다.

### 5.5 공유 Excel 연계 모듈

회사 공유폴더의 월별 Excel 파일을 읽고 담당자 승인 후 실제 출고·선적수량을 기록한다. 쓰기 전 백업, 파일 변경 감지, 잠금 확인, 수식 재계산과 저장 검증을 수행한다.

## 6. 공통 PO 관리

### 6.1 등록과 추출

영업담당자가 내부 웹사이트에서 PO PDF를 업로드한다. 시스템은 고객사와 문서양식을 식별하고 다음 정보를 추출한다.

#### 공통정보

- 고객사명
- PO 번호
- 주문일
- 품목코드
- 품명
- 주문수량
- 단가
- 통화
- 공급가액
- 요청 납기일
- 고객 담당자 정보
- 비고 또는 특별 요청사항

#### 해외 추가정보

- Invoice No.
- EXW Date
- ETD
- ETA

공급가액은 `주문수량 × 단가`로 다시 계산한다. PO 기재금액과 계산값이 허용 오차를 벗어나면 자동 확정하지 않고 예외로 보낸다. 납품·선적 장소는 공통 필수정보로 관리하지 않는다.

### 6.2 고객별 양식

고객마다 PO 양식과 출력 Excel 양식이 다르며, 같은 고객의 양식은 대체로 일정하다고 가정한다. 시스템은 고객별로 다음 설정을 관리한다.

- PO 인식 규칙과 필드 위치
- 고객별 Excel 템플릿과 셀 매핑
- 국내·해외 기본구분
- 고객사 문서코드
- 분할납품 허용 여부
- 담당 영업사원과 메일 수신자

처음 보는 양식이나 인식 신뢰도가 낮은 필드는 담당자 검토 후 저장한다.

### 6.3 중복 방지와 상태

동일 고객사의 동일 PO 번호는 중복 등록을 차단한다. PO는 다음 상태를 갖는다.

- 검토 대기
- 처리 중
- 생산요청 승인 대기
- 출고·선적 준비
- 부분출고
- Excel 반영 대기
- 완료
- 예외
- 취소

## 7. 국내 발주·출고 흐름

### 7.1 PO와 주문등록

1. 영업담당자가 PO PDF를 업로드한다.
2. 시스템이 PO 정보를 추출하고 담당자가 결과를 확인한다.
3. 확정된 주문정보를 공통 데이터로 저장하고 고객별 Excel을 생성한다.
4. 검증된 정보를 iCUBE의 회사 기존 주문등록 업무에 반영한다.

### 7.2 재고 확인과 생산요청

1. `일별재고현황`에서 품명으로 국내 회사 창고의 실제 제품재고를 조회한다.
2. 조회 재고는 다른 담당자의 미확정 출고계획이 반영되지 않은 참고값으로 표시한다.
3. 부족 가능성이 있으면 해당 PO 영업담당자에게 예외 작업함과 Outlook으로 알린다.
4. 담당자가 다른 영업담당자의 출고 시기와 수량 및 고객 상황을 확인한다.
5. 담당자가 생산요청 수량을 직접 입력한다.
6. 납기일은 등록일로부터 14일 후를 기본 제안하되 담당자가 수정할 수 있다. 이 날짜는 ERP 등록 기본값이며 핵심 일정판단 기준으로 사용하지 않는다.
7. 영업담당자가 승인하면 `발주등록(수입_기타)`에 등록한다.

생산요청 초안에는 대상 PO, 고객사, 품목, 주문수량, 조회 재고, 담당자 입력 생산요청 수량, 납기일, 등록사유와 ERP 대상 메뉴를 표시한다.

### 7.3 일반납품과 분할납품

일반 고객은 PO 전체 수량을 한 번에 납품하는 것을 기본으로 한다. 특정 고객만 고객사 기준정보에서 `분할납품 허용`으로 설정한다.

분할납품 고객은 다음을 관리한다.

- PO 총수량
- 회차별 예정 납품일과 예정수량
- 회차별 실제 납품일과 실제수량
- 누적 실제 납품수량
- 잔량

계산식은 `잔량 = PO 총수량 - 누적 실제 납품수량`이다. 납품일과 수량은 고객의 이메일·전화·메신저 협의 결과를 담당자가 직접 입력·수정한다. 총 실제수량이 PO 총수량을 초과하면 확정을 차단한다. 잔량이 0이 될 때까지 PO 상태는 `부분출고`로 유지한다.

### 7.4 출고 준비와 문서

1. 각 납품 회차의 출고일 전날 품목, 수량, 출고일, 고객사와 문서정보를 구매팀에 Outlook으로 자동 발송한다.
2. 고객사별 양식으로 거래명세서 Excel을 생성한다.
3. 거래명세서를 PDF로 저장하고 인쇄 작업을 준비한다.
4. iCUBE에 출고의뢰서를 등록하고 인쇄 작업을 준비한다.
5. 구매팀에는 전자파일을 전달하고 종이 대면 전달은 담당자 할 일로 생성한다.
6. 출고 당일 거래명세서 PDF를 고객사에 자동 발송한다.
7. iCUBE 출고전표 인쇄와 영업팀 지정 바구니 보관을 담당자 할 일로 생성한다.

종이 출력·대면 전달·바구니 보관은 담당자가 완료 버튼을 눌러야 완료로 기록한다. 향후 사내 규정이 허용하면 동일 문서의 전자 전달로 전환할 수 있다.

### 7.5 실제 출하수량

정상 건은 거래명세서 수량을 실제 출하수량 후보로 사용한다. 계획과 실제 수량이 다르면 자동 변경하지 않고 담당자 확인을 요구한다. 확정된 수량은 공유 Excel 반영 대기 상태로 이동한다.

## 8. 해외 중계무역 흐름

### 8.1 PO와 출고 가능수량 판단

1. PO PDF를 업로드하고 해외 중계무역 주문으로 분류한다.
2. iCUBE `발주미납현황(수입)`에서 해당 품목의 잔량을 조회한다.
3. 담당자는 이 잔량을 기준으로 현재 납품 가능수량을 주로 판단한다.
4. 중국 공장의 실제 물리재고는 `발주미납현황(수입)` 잔량과 다른 값이다. 필요할 때만 메신저로 공장 담당자에게 확인하고 시스템에 참고사항으로 기록한다.

### 8.2 생산요청

잔량이 부족하거나 추가 생산이 필요하다고 담당자가 판단하면 생산요청 알림을 생성한다. 생산요청 수량은 시스템이 계산·확정하지 않고 영업담당자가 직접 입력한다. 납기일은 등록 당일을 기본값으로 제안하되 수정할 수 있다. 승인 후 `발주등록(수입_기타)`에 등록한다.

### 8.3 QY Invoice

1. 담당자가 EXW Date를 입력한다.
2. 운송방식은 `VSL`을 기본값으로 제안하고 필요한 경우 `AIR`로 변경한다.
3. 시스템이 QY Invoice No.를 제안하고 담당자가 최종 확인·수정한다.
4. 고객별 Invoice Excel을 생성해 중국 공장에 Outlook으로 발송한다.

QY Invoice No. 형식은 다음과 같다.

`QY + EXW Date(YYMMDD) + '-' + 연속번호 + 고객사코드 + '(' + 운송방식 + ')'`

예: `QY261013-40CHVN(VSL)`

- 연속번호는 초기화하지 않고 계속 증가한다.
- 같은 번호의 중복 저장·발송을 차단한다.
- 고객사코드는 고객사별로 관리한다. `CHVN`은 CHEMTRO VINA CO., LTD의 코드다.

### 8.4 QP·BL 자동 수신과 연결

중국 공장은 QY Invoice를 확인하고 출하가 가능하면 별도의 새 메일로 QP 번호, ETD, ETA와 BL Excel을 전달한다. 기존 발송 메일의 회신 여부에는 의존하지 않는다.

1. 지정 Outlook 메일함에서 등록된 중국 공장 발신자의 새 메일을 감시한다.
2. 제목에서 `QP...` 번호를 추출한다.
3. 제목의 날짜, 연속번호와 고객사코드를 이용해 연결된 `QY...` Invoice를 찾는다.
4. QP 문서의 업체별 중국어 부가문구는 원문으로 저장하지만 연결 필수값에서는 제외한다.
5. 메일 본문에서 ETD와 ETA를 추출한다.
6. 첨부된 Excel에 `BL` 시트가 있는지 확인한다.
7. BL 시트 이미지에서 `ON BOARD` 날짜를 인식한다.
8. Invoice 수량과 BL의 실제 선적수량을 비교한다.

QY와 QP의 관계 예시는 다음과 같다.

- QY Invoice: `QY260922-39CHVN(VSL)`
- QP·BL: `QP260922-39CHVN托盘`

`托盘` 같은 부가문구는 업체에 따라 달라질 수 있다.

### 8.5 해외 검증과 후속 처리

- QP 번호를 QY Invoice와 연결하지 못하면 예외 처리한다.
- 메일의 ETD와 BL의 `ON BOARD` 날짜가 다르면 자동 확정하지 않는다.
- Invoice 수량과 BL 실제 선적수량이 다르면 자동 변경하지 않는다.
- 담당자가 불일치를 검토·수정·승인한 뒤 후속 처리를 재개한다.
- 정상 검증 완료 즉시 고객사에 ETD·ETA와 선적상태 안내 메일을 자동 발송한다.
- iCUBE 수입선적등록과 입고처리를 수행하고 각각의 성공 여부를 확인한다.
- 두 ERP 처리가 끝나면 내부 영업관리팀에 완료 메일을 발송한다.
- 확정된 실제 선적수량은 공유 Excel 반영 대기 상태로 이동한다.

## 9. 공유폴더 월별 Excel 연계

### 9.1 파일 구조

국내·해외 실적은 하나의 월별 Excel 파일의 한 시트에서 관리한다. 매월 새 파일을 만들고 담당자별 행과 날짜 열을 구성한다. 주요 열은 다음과 같다.

- 담당자
- 거래처명
- 모델명
- Currency
- 단가
- 계획수량
- 계획금액
- 실적수량
- 실적금액
- 차이
- 날짜별 출고·선적수량

### 9.2 행과 열 식별

행은 다음 복합기준으로 찾는다.

`담당자 + 거래처명 + 모델명 + 통화 + 단가`

국내는 실제 출하일, 해외는 실제 선적일에 해당하는 날짜 열을 찾는다. 일치 행이나 날짜 열이 없으면 임의로 생성하지 않고 예외 작업함으로 보낸다.

### 9.3 반영 전 승인

시스템은 Excel을 즉시 수정하지 않고 `Excel 반영 대기` 상태에서 담당자에게 다음 미리보기를 제공한다.

- 대상 월, 파일명과 시트명
- 대상 행의 담당자·거래처·모델명·통화·단가
- 대상 날짜 열
- 입력 전 셀 값
- 신규 또는 합산할 수량
- 반영 후 예상 실적수량·실적금액
- 근거 문서: 국내 거래명세서 또는 해외 QP·BL

담당자는 다음 작업을 할 수 있다.

- 확인 후 반영
- 대상 위치 수정
- 사유를 입력한 수량 수정
- 반려

승인 이후 원본 파일이 바뀌었으면 기존 승인을 무효화하고 최신 파일로 미리보기를 다시 생성한다.

### 9.4 쓰기와 검증

1. 원본 파일을 복구 가능한 위치에 백업한다.
2. 파일 잠금 여부와 승인 당시 파일 버전을 확인한다.
3. 승인된 셀에 수량을 기록한다.
4. 동일 업무 건의 재처리는 중복 입력을 막고 별도 출고 건은 합산한다.
5. Excel 수식을 다시 계산한다.
6. 실적수량, 실적금액, 차이와 상단 담당자별 실적의 계산 결과를 검증한다.
7. 저장 성공 여부와 변경 전후 값을 감사이력에 기록한다.

파일이 잠겨 있으면 제한된 횟수만큼 재시도하고, 계속 실패하면 예외 작업함과 Outlook으로 알린다.

## 12. 예외 처리

다음 경우 자동 처리를 중단하고 예외 작업함에 등록한다.

- 알 수 없는 고객사 또는 새로운 PO 양식
- 필수정보 누락 또는 낮은 문자인식 신뢰도
- 중복 PO
- 공급가액 계산 불일치
- iCUBE 조회·등록 실패
- 재고 부족 가능성
- 생산요청 승인 대기 또는 반려
- QY·QP 연결 실패
- 미등록 중국 공장 발신자
- ETD와 `ON BOARD` 날짜 불일치
- Invoice와 BL 수량 불일치
- Outlook 발송·수신 실패
- 공유 Excel 행 또는 날짜 열 검색 실패
- 공유 Excel 파일 잠금 또는 승인 후 파일 변경
- 중복 ERP 등록·메일 발송·Excel 쓰기 가능성

예외 건은 발생 원인, 해결에 필요한 입력, 담당자와 재처리 지점을 표시한다. 일시 장애는 자동 재시도하되 업무값이 불명확하거나 중복 위험이 있는 경우에는 자동 재시도하지 않는다.

## 13. 보안과 운영

- 회사 계정 기반 로그인과 역할별 최소권한을 적용한다.
- Outlook과 iCUBE 연계 계정은 개인 비밀번호를 코드에 저장하지 않는다.
- 원본 PO, Invoice와 BL에는 업무상 필요한 사용자만 접근할 수 있다.
- 다운로드·수정·메일 발송·ERP 등록·Excel 반영을 감사기록에 남긴다.
- 원본 문서와 변경된 공유 Excel 백업은 회사 문서보존 정책에 맞춰 보관한다.
- 연계 장애가 발생해도 PO와 승인 데이터는 유실되지 않아야 한다.
- 재처리 시 이미 성공한 단계는 반복하지 않고 실패한 단계부터 이어서 수행한다.

## 14. 인수 기준

### 14.1 PO와 데이터

- 등록된 고객별 PO PDF에서 합의된 필수항목을 추출할 수 있다.
- 자동 추출값과 담당자 수정값을 구분해 기록한다.
- 동일 고객사의 동일 PO 번호를 중복 등록할 수 없다.
- 공급가액 계산과 원문 비교 결과를 표시한다.

### 14.2 국내

- `일별재고현황` 조회값을 주문과 연결해 표시한다.
- 생산요청 수량은 영업담당자가 직접 입력·승인해야만 ERP에 등록된다.
- 일반납품과 고객별 분할납품을 구분한다.
- 분할납품의 누적 실제수량과 잔량을 정확히 계산하며 초과출하를 차단한다.
- 납품 회차별로 구매팀 안내, 거래명세서와 출고 업무를 처리한다.

### 14.3 해외

- `발주미납현황(수입)` 잔량을 조회해 주문과 연결한다.
- VSL을 기본 운송방식으로 제안하고 AIR로 변경할 수 있다.
- 중복되지 않는 QY Invoice No.를 제안하고 담당자가 수정·확정할 수 있다.
- 새 Outlook 메일의 제목에서 QP 번호를 읽어 QY Invoice와 연결한다.
- 메일의 ETD·ETA와 BL 이미지의 `ON BOARD` 날짜를 읽고 비교한다.
- 수량·날짜 불일치 시 담당자 승인 전까지 고객 안내와 후속 ERP 처리를 중단한다.
- 정상 검증 완료 후 고객 안내, 수입선적등록, 입고처리와 내부 영업관리팀 알림을 순서대로 수행한다.

### 14.4 공유 Excel

- 출고·선적일의 연월에 맞는 공유 Excel 파일을 선택한다.
- 담당자·거래처명·모델명·통화·단가로 올바른 행을 찾는다.
- 담당자가 대상 셀과 수량을 미리 확인하기 전에는 Excel을 수정하지 않는다.
- 승인 후 파일이 변경되면 재승인을 요구한다.
- 입력 전 백업과 입력 후 수식 재계산·저장 검증을 수행한다.
- 같은 업무 건을 재처리해도 수량이 중복 입력되지 않는다.

### 14.5 추적성과 안정성

- PO 원본부터 ERP, 메일, 문서와 Excel 반영까지 주문별 이력을 조회할 수 있다.
- 외부 시스템 장애 후 재처리해도 중복 ERP 등록과 중복 메일이 발생하지 않는다.
- 예외의 원인과 담당자 조치 결과가 기록된다.

## 15. 구축 전 확인 및 검증 절차

3. Microsoft 365 관리자로부터 지정 메일함 읽기·발송 권한을 부여받는다.
4. 고객별 PO, 출력 Excel, Invoice와 거래명세서 샘플로 매핑을 검증한다.
5. 월별 공유 Excel의 파일명, 시트명, 날짜 표기, 수식과 백업 위치를 확인한다.
6. 프린터와 종이문서 처리 절차를 확인하고 자동 인쇄 또는 인쇄 대기 방식 중 회사 정책에 맞는 방식을 적용한다.
7. 실제 업무와 분리된 시험환경에서 국내 일반납품, 분할납품, 해외 VSL·AIR, 날짜·수량 불일치와 외부 시스템 장애 시나리오를 검증한다.
