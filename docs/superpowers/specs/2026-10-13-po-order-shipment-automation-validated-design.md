# PO 발주·출고 업무 자동화 검증완료 설계명세서

- 작성일: 2026-10-13
- 문서 상태: Grill 검증 완료
- 대상 독자: 영업·구매·영업관리 현업 담당자, 시스템 개발·운영 담당자
- 기준 시스템: 더존 iCUBE, Microsoft 365 Outlook, 회사 공유폴더 월별 Excel
- 1차 시범 고객: 범진전자, CHEMTRO VINA CO., LTD

## 1. 목적

고객 PO 접수부터 재고 확인, 생산요청, 국내 출고와 해외 중계무역 선적까지의 진행상태를 내부 웹 시스템에서 관리한다. 반복적인 문서 생성과 보내는 메일은 자동화하고, 업무 판단이 필요한 수량·날짜·ERP 등록은 영업담당자가 확인하거나 입력한다.

시스템은 다음 결과를 달성해야 한다.

- 고객별로 다른 PO PDF를 공통 주문 데이터로 관리한다.
- 국내 일반납품과 분할납품의 회차별 수량 및 잔량을 관리한다.
- 해외 QY Invoice와 QP 정보를 연결하고 실제 선적정보를 관리한다.
- 생산요청, 문서 생성, 메일 발송과 ERP 처리이력을 주문 단위로 추적한다.
- 중복 PO, 중복 Invoice No., 중복 ERP 등록과 중복 메일 발송을 방지한다.
- 담당자가 회사 공유 Excel에 옮겨 적을 실제 수량과 기준정보를 명확히 보여준다.

## 2. 확정된 자동화 경계

### 2.1 시스템이 처리하는 업무

- 내부 웹사이트에서 PO PDF 업로드
- 고객별 PO 정보 추출과 검증
- 주문, 납품회차, 잔량, 해외 선적정보와 업무상태 관리
- 고객별 Excel, QY Invoice와 거래명세서 생성
- 더존 iCUBE 조회·등록 연계 또는 수동등록 지원
- 중국 공장, 고객, 구매팀과 영업관리팀에 보내는 Outlook 메일 생성·발송
- 생산요청, 예외와 정정 이력 관리
- 실제 출고·선적수량의 시스템 내 보관과 Excel 입력용 정보 표시

### 2.2 담당자가 직접 처리하는 업무

- 개인 Outlook에서 고객 PO와 중국 공장 BL 메일 확인
- PO PDF를 시스템에 업로드
- 중국 공장 메일과 BL을 보고 QP No., ON BOARD 날짜, ETD, ETA와 실제 선적수량 입력
- 생산요청 수량 판단과 단독 승인
- iCUBE 자동연계가 불가능할 때 ERP 수동등록
- 회사 공유폴더 월별 Excel에 최종 선적수량과 출하수량 직접 입력
- 종이문서 인쇄·대면 전달과 지정 바구니 보관

### 2.3 제외 범위

- 개인 Outlook 수신메일 자동검색·자동수집
- 고객 PO 메일과 중국 공장 BL 메일 자동판독
- BL Excel 업로드·보관 및 BL 이미지 OCR
- 공유폴더 Excel 읽기·쓰기·수식검증
- 공유 Excel 입력 완료 여부 추적
- FCST와 안전재고 배수를 이용한 생산요청 수량 자동계산
- 영업담당자 간 미확정 출고계획을 이용한 가용재고 자동배분
- 중국 공장 실제 물리재고의 상시 자동조회
- 예외 미처리 시 영업관리팀·관리자에게 자동 확대 알림
- 생산요청에 대한 팀장 또는 2차 승인
- 제품이 정해지지 않은 차기 ERP 연계

## 3. 설계 원칙

1. **웹 시스템이 주문정보의 기준 원본이다.** 공유 Excel은 기존 실적관리용으로 유지하되 시스템이 직접 수정하지 않는다.
2. **판단은 담당자가 한다.** 생산요청 수량, 해외 선적정보와 불일치는 영업담당자가 확인한다.
3. **외부 쓰기는 중복되지 않아야 한다.** ERP와 발신메일은 업무 식별자와 처리상태를 사용해 재시도하더라도 같은 작업을 반복하지 않는다.
4. **완료 기록을 덮어쓰지 않는다.** 완료 건의 변경은 별도 정정업무로 생성한다.
5. **고객별 차이는 기준정보로 관리한다.** PO 양식, 고객사 코드, 문서양식, 메일 수신자, 단위환산과 분할납품 여부를 설정으로 관리한다.
6. **최소한의 데이터만 저장한다.** 수신메일과 BL 원본은 시스템에 저장하지 않고 담당자가 입력한 업무값만 보관한다.

| 영업담당자 | 본인 PO 등록·검토, 납품회차 관리, 생산요청 입력·단독 승인, 해외 선적정보 입력, 예외 처리 |
| 구매팀 | 국내 출고 일정과 전달 문서 조회, 전달업무 완료 표시 |

| 관리자 | 사용자 권한, 메일계정, ERP 연계, 고객·품목·단위·문서양식 설정 |

모든 수정, 승인, 반려, ERP 등록, 문서 생성과 메일 발송에는 사용자, 처리일시, 변경 전후 값과 사유를 기록한다.

## 5. 시스템 구성

### 5.1 내부 웹 애플리케이션

회사 계정으로 로그인하는 내부 업무 사이트다. PO 업로드, 주문 조회, 납품·선적정보 입력, 생산요청 승인, 예외 처리와 기준정보 관리를 제공한다.

### 5.2 문서 처리 모듈

- 고객별 PO PDF 분류와 필드 추출
- 필수값, 공급가액과 단위 검증
- 고객별 Excel, QY Invoice, 거래명세서와 출고 관련 문서 생성
- 원본 PO와 생성 문서의 버전·연결관계 관리

### 5.3 iCUBE 연계 모듈

- 국내: `일별재고현황` 조회
- 해외: `발주미납현황(수입)` 조회
- 국내·해외 생산요청: `발주등록(수입_기타)` 등록
- 해외 후속업무: 수입선적등록과 입고처리
- 국내 후속업무: 기존 주문등록, 출고의뢰서와 출고전표 업무 지원

본 개발 전에 조회 2종과 시험용 `발주등록(수입_기타)` 1건을 대상으로 기술검증을 수행한다. 연계수단은 공식 인터페이스, 회사와 더존이 승인한 DB·파일, 승인된 화면 자동화 순으로 검토한다. 자동연계가 불가능하면 시스템이 입력값을 보여주고 담당자가 iCUBE에 수동등록한다.

### 5.4 Outlook 발신 모듈

담당자의 개인 Outlook 계정을 이용해 보내는 메일만 처리한다. 수신메일은 읽지 않는다. 감시·발신 계정은 관리자 화면에서 교체할 수 있으며 계정 연결이 끊기면 본인과 시스템 관리자에게 알린다.

### 5.5 공유 Excel 입력지원

시스템은 공유 Excel 파일에 접근하지 않는다. 담당자가 직접 입력할 수 있도록 다음 값을 한 화면에 표시한다.

- 담당자
- 거래처명
- 모델명
- 통화
- 단가
- 국내 실제 출하일 또는 해외 실제 선적일
- 최종 출하수량 또는 선적수량

Excel 입력 여부는 시스템 상태나 주문 완료조건에 포함하지 않는다.

## 6. 공통 PO 관리

### 6.1 등록과 추출

영업담당자가 고객 메일에서 받은 PO PDF를 내부 웹사이트에 업로드한다. 시스템은 고객사와 문서양식을 식별하고 다음 정보를 추출한다.

#### 공통정보

- 고객사명
- PO 번호
- 주문일
- 품목코드
- 품명
- 주문수량과 단위
- 단가와 통화
- 공급가액
- 요청 납기일
- 고객 담당자 정보
- 비고 또는 특별 요청사항

#### 해외 추가정보

- Invoice No.
- EXW Date
- ETD
- ETA와 확정상태

납품·선적 장소는 공통 필수정보로 관리하지 않는다.

### 6.2 금액과 단위

- 공급가액은 주문수량과 단가로 다시 계산한다.
- 원본 계산값은 충분한 소수점 자릿수로 보관한다.
- 화면·문서의 반올림과 허용오차는 고객사·통화별로 설정한다.
- 수량에는 단위를 함께 저장한다.
- 고객 단위와 iCUBE 기준단위가 다르면 승인된 품목별 환산비율이 있을 때만 자동환산한다.
- 환산규칙이 없으면 담당자가 확인한다.

### 6.3 품목 식별

iCUBE 품목코드를 기준 식별자로 사용한다. 고객 품목명·코드가 iCUBE와 다르면 고객 품목과 iCUBE 품목코드의 매핑을 관리한다. 품명검색은 최초 매핑을 만들 때만 사용한다.

### 6.4 OCR 단계적 적용

- 고객 양식별 초기 20건은 담당자가 모든 필수항목을 확인한다.
- 20건 연속 오류가 없고 필수필드 신뢰도가 기준 이상이면 정상 건만 자동확정으로 전환할 수 있다.
- PO 번호, 수량, 단가와 통화의 신뢰도가 낮으면 자동화 이후에도 담당자가 확인한다.
- 1차 버전은 회사 내부에서 실행되는 OCR을 사용한다.
- 실제 고객문서를 외부 클라우드 OCR로 전송하려면 별도 보안승인이 필요하다.

### 6.5 중복과 수정본

- 고객사와 PO 번호가 같고 파일내용도 같으면 중복으로 차단한다.
- PO 번호는 같지만 내용이 다르면 수정본으로 등록한다.
- 담당자에게 변경 전후를 보여주고 승인 후 새 버전을 적용한다.
- 이미 출고된 수량은 수정할 수 없고 미출고 잔량만 조정한다.

## 7. 국내 발주·출고

### 7.1 시범 고객

국내 1차 시범운영 고객은 범진전자다. 범진전자를 통해 일반납품과 분할납품을 함께 검증한다.

### 7.2 주문과 재고

1. PO PDF를 업로드하고 추출결과를 확정한다.
2. 고객별 Excel을 생성하고 iCUBE 기존 주문등록 업무에 반영한다.
3. `일별재고현황`에서 iCUBE 품목코드로 국내 창고 재고를 조회한다.
4. 조회값은 다른 담당자의 미확정 출고계획이 반영되지 않은 참고값으로 표시한다.
5. 부족 가능성이 있으면 해당 영업담당자에게만 알린다.

### 7.3 생산요청

1. 담당자가 다른 출고계획과 고객 상황을 확인한다.
2. 생산요청 수량을 직접 입력한다.
3. 납기일은 등록일로부터 14일 후를 기본 제안하며 수정할 수 있다.
4. 해당 영업담당자가 단독 승인한다.
5. `발주등록(수입_기타)`에 자동등록하거나 수동등록한다.
6. 수동등록 시 ERP 문서번호를 필수 입력한다. 문서번호가 없는 업무만 사유로 대체한다.

### 7.4 일반납품과 분할납품

일반 고객은 PO 전체수량을 한 번에 납품하는 것을 기본으로 한다. 분할납품은 고객사 기준정보에서 허용된 고객에게만 적용한다.

분할납품은 다음을 관리한다.

- PO 총수량
- 회차별 예정 납품일과 예정수량
- 회차별 실제 납품일과 실제수량
- 누적 실제 납품수량
- 잔량

`잔량 = PO 총수량 - 누적 실제 납품수량`으로 계산한다. 실제수량 합계가 PO 수량을 초과하면 확정을 차단한다.

구매팀 안내메일 발송 전에는 일정을 자유롭게 수정할 수 있다. 발송 후에는 변경사유를 입력하고 기존 문서를 취소한 뒤 구매팀 변경메일과 새 문서를 생성한다. 완료 회차는 직접 수정하지 않고 정정업무를 만든다.

### 7.5 출고 준비와 완료

1. 출고일 전날 구매팀 안내메일을 생성·발송한다.
2. 고객사별 거래명세서 Excel과 PDF를 생성한다.
3. iCUBE 출고의뢰서를 등록하고 인쇄 작업을 준비한다.
4. 구매팀 전자파일 전달과 종이 대면전달 업무를 표시한다.
5. 출고 당일 거래명세서 PDF를 고객사에 발송한다.
6. 출고전표 인쇄와 지정 바구니 보관을 담당자 업무로 표시한다.
7. 담당자가 실제 출하일과 실제 출하수량을 확정한다.

## 8. 해외 중계무역

### 8.1 시범 고객과 출고 가능수량

해외 1차 시범운영 고객은 CHEMTRO VINA CO., LTD다.

1. PO를 해외 중계무역 주문으로 분류한다.
2. `발주미납현황(수입)`에서 품목별 잔량을 조회한다.
3. 담당자는 해당 잔량을 기준으로 납품 가능수량을 판단한다.
4. 중국 공장의 실제 물리재고는 별개 값이며 필요할 때만 메신저로 확인한다.

### 8.2 생산요청

잔량이 부족하거나 추가생산이 필요하면 해당 영업담당자에게만 알린다. 담당자가 생산요청 수량을 직접 입력하고 단독 승인한다. 납기일은 등록 당일을 기본값으로 제안한다. 승인 후 `발주등록(수입_기타)`에 자동 또는 수동으로 등록한다.

### 8.3 QY Invoice

1. 담당자가 EXW Date를 입력한다.
2. 운송방식은 `VSL`을 기본값으로 제안하며 `AIR`로 변경할 수 있다.
3. 시스템이 QY Invoice No.를 제안하고 담당자가 확정한다.
4. 고객별 Invoice Excel을 생성해 중국 공장에 발송한다.

번호형식은 다음과 같다.

`QY + EXW Date의 YYMMDD + '-' + 연속번호 + 고객사코드 + '(' + 운송방식 + ')'`

예: `QY261013-40CHVN(VSL)`

- 연속번호는 초기화하지 않고 계속 증가한다.
- 중복번호 저장·발송을 차단한다.
- 취소번호는 `VOID` 상태와 사유를 남기고 재사용하지 않는다.
- 고객사코드는 고객사별로 관리한다.

### 8.4 QP와 선적정보 입력

1. 담당자가 중국 공장 메일과 BL을 개인 Outlook에서 확인한다.
2. 시스템에 QP No.를 입력한다.
3. 시스템이 날짜·연속번호·고객사코드로 연결할 QY를 제안한다.
4. 담당자가 QY와 QP 연결을 확정한다.
5. 담당자가 ON BOARD 날짜, ETD, ETA 상태와 실제 선적수량을 입력한다.

QY 여러 건과 BL 여러 건의 연결을 허용한다. 현재 일반적인 1:1 건은 자동 제안하고 합배송·분할선적은 담당자가 직접 관계를 선택한다. QP의 업체별 중국어 부가문구는 연결 필수값으로 사용하지 않는다.

BL 원본과 중국 공장 수신메일은 시스템에 저장하지 않는다.

### 8.5 날짜와 수량 검증

- 해외 실제 선적일은 BL의 `ON BOARD` 날짜다.
- 정상적으로 ON BOARD 날짜와 ETD는 같은 날짜로 취급한다.
- 두 날짜가 다르면 자동확정하지 않고 담당자가 확인한다.
- 최종 확인 시 ON BOARD 날짜를 실제 선적일로 사용하고 메일 ETD는 참고이력으로 남긴다.
- ETA는 `확정`, `예정`, `전후` 상태를 함께 저장한다.
- Invoice 수량과 실제 선적수량이 다르면 담당자가 사유를 확인하고 승인한다.

### 8.6 해외 후속업무

1. 선적정보 확정 후 고객사 선적안내 메일을 생성·발송한다.
2. iCUBE 수입선적등록과 입고처리를 수행한다.
3. 두 ERP 처리가 끝나면 내부 영업관리팀 완료메일을 발송한다.
4. 담당자가 공유 Excel에 입력할 실제 선적정보를 화면에 표시한다.

## 9. 보내는 메일 자동화

### 9.1 대상메일

- 중국 공장 QY Invoice
- 고객 해외 선적상태 안내
- 국내 출고 전날 구매팀 안내
- 국내 고객 거래명세서
- 내부 영업관리팀 완료 안내

### 9.2 시범운영

- 첫 2주는 메일을 Outlook 임시보관함에 생성한다.
- 담당자가 수신자, 제목, 본문과 첨부파일을 확인한 후 발송한다.
- 목표 오류율을 충족한 뒤 정상 건만 자동발송으로 전환한다.
- 예외 건은 계속 담당자가 확인한다.
- 야간·휴일에는 문서와 메일을 준비할 수 있지만 외부 자동발송은 다음 영업시간까지 대기한다.

### 9.3 수신자와 첨부 통제

- 고객사 기준정보에 등록된 외부주소만 자동사용한다.
- 주문 고객사와 첨부문서의 고객사 ID가 일치해야 한다.
- 등록되지 않은 주소 추가 또는 고객사 불일치가 있으면 자동발송을 차단한다.
- 담당자 변경은 관리자 또는 지정 영업담당자가 승인한다.

## 10. 공유 Excel 수동입력

- 월별 공유 Excel은 기존 방식대로 영업관리팀 또는 담당자가 준비한다.
- 시스템은 파일, 행, 열, 수식, 환율과 실적금액을 읽거나 수정하지 않는다.
- 시스템에 확정된 실제 수량과 날짜를 Excel 입력용 화면에 표시한다.
- 사용자가 화면 값을 참고해 회사 공유폴더 Excel에 직접 입력한다.
- Excel 입력 완료버튼, 완료이력과 정확성 검증은 제공하지 않는다.
- 공유 Excel 입력은 주문 완료조건에 포함하지 않는다.

## 11. 상태와 완료 기준

PO는 다음 상태를 갖는다.

- 검토 대기
- 처리 중
- 생산요청 승인 대기
- 출고·선적 준비
- 부분출고
- 완료
- 예외
- 취소

PO 잔량이 0이고 필요한 ERP·문서·메일 업무가 끝났으며 실제 수량이 시스템에서 확정되면 완료처리한다. 공유 Excel 입력 여부는 확인하지 않는다.

완료 후 변경이 필요하면 직접 덮어쓰지 않고 `정정` 업무를 생성한다. 원래 값, 정정 값, 사유와 담당자를 기록하고 ERP·메일 중 다시 처리할 대상을 선택한다.

## 12. 예외 처리

다음 경우 자동처리를 중단하고 해당 영업담당자에게만 알린다.

- 알 수 없는 고객사 또는 새로운 PO 양식
- 필수정보 누락 또는 낮은 OCR 신뢰도
- 중복 PO 또는 수정본 담당자 승인 대기
- 공급가액·단위·환산 불일치
- iCUBE 조회·등록 실패
- 재고 부족 가능성
- 생산요청 승인 대기 또는 반려
- QY·QP 연결실패 또는 여러 후보
- ON BOARD 날짜와 ETD 불일치
- Invoice와 실제 선적수량 불일치
- Outlook 발송실패
- 중복 ERP 등록 또는 메일 발송 가능성

예외를 영업관리팀이나 관리자에게 자동 확대하지 않는다. 미처리 예외는 담당자 화면에 계속 표시한다.

## 13. 보안과 운영

- 회사 계정 로그인과 역할별 최소권한을 적용한다.
- Outlook과 iCUBE 계정 비밀번호를 코드나 설정파일에 저장하지 않는다.
- 수신메일과 BL 원본은 시스템이 읽거나 저장하지 않는다.
- PO와 생성문서는 업무상 필요한 사용자만 접근할 수 있다.
- 다운로드, 수정, 승인, ERP 등록과 발신메일을 감사기록에 남긴다.
- 회사 문서보존 정책을 적용한다. 정책이 정해지기 전에는 삭제기능을 비활성화한다.
- 데이터베이스의 최대 허용 손실은 15분, 문서파일은 1시간을 목표로 한다.
- 장애 후 4시간 안에 핵심 PO 조회와 수동처리를 복구한다.
- 월 1회 복구시험을 수행한다.

## 14. 시범운영과 전환

### 14.1 데이터 이관

- 완료된 과거 PO는 이관하지 않는다.
- 오픈 상태이거나 잔량이 남은 PO만 이관한다.
- 이관 후 담당자가 PO 수량, 누적출고와 잔량을 확인한다.

### 14.2 성공지표

시범운영 1개월 동안 다음을 측정한다.

- 등록된 고객 양식의 PO 필수정보 추출 정확도 95% 이상
- 정상 업무의 80% 이상이 수동 재입력 없이 처리
- 중복 ERP 등록과 중복 발신메일 0건
- PO 실제 수량과 잔량 관리오류 0건
- 기존 대비 PO 1건당 담당자 작업시간 50% 이상 감소

공유 Excel의 입력 완료와 값 정확성은 시스템 성공지표에서 제외한다.

### 14.3 중단과 복구

시범기간에는 기존 업무방식을 병행하고 웹 시스템 결과를 매일 대조한다. 중복 ERP·메일 오류가 1건이라도 발생하거나 핵심 업무가 4시간 이상 중단되면 외부 자동쓰기를 끄고 수동방식으로 전환한다. 수정과 재검증 후 다시 활성화한다.

### 14.4 정식 전환 승인

사용자, 영업관리 책임자와 IT·유지보수 담당자가 성공지표와 오류내역을 함께 검토한다. 해결되지 않은 중대한 오류가 있으면 외부 자동쓰기를 활성화하지 않는다.

## 15. 인수 기준

### 15.1 PO

- 범진전자와 CHEMTRO VINA PO의 필수정보를 추출할 수 있다.
- 자동 추출값과 담당자 수정값을 구분해 기록한다.
- 동일파일 중복과 같은 PO 번호의 수정본을 구분한다.
- 공급가액, 단위와 품목코드 매핑을 검증한다.

### 15.2 국내

- `일별재고현황` 값을 주문과 연결해 표시한다.
- 담당자가 입력·단독 승인한 생산요청만 ERP에 등록한다.
- 일반납품과 범진전자 분할납품을 구분한다.
- 누적 실제수량과 잔량을 정확히 계산하고 초과출하를 차단한다.
- 회차별 구매팀 안내, 거래명세서와 출고업무를 처리한다.

### 15.3 해외

- `발주미납현황(수입)` 잔량을 주문과 연결한다.
- VSL을 기본으로 제안하고 AIR로 변경할 수 있다.
- 중복되지 않는 QY 번호를 제안하고 취소번호를 재사용하지 않는다.
- 담당자가 입력한 QP 번호에 연결할 QY를 제안하고 다대다 관계를 저장한다.
- ON BOARD 날짜, ETD, ETA 상태와 실제 선적수량을 관리한다.
- 날짜·수량 불일치 시 담당자 확인 전 후속처리를 중단한다.
- 검증 후 고객안내, 수입선적등록, 입고처리와 내부 완료메일을 순서대로 수행한다.

### 15.4 발신메일과 ERP

- 첫 2주 동안 대상메일을 Outlook 임시보관함에 생성한다.
- 등록된 수신자와 일치하는 고객문서만 첨부한다.
- 재시도해도 같은 ERP 등록이나 메일발송이 반복되지 않는다.
- iCUBE 자동연계가 불가능하면 수동등록용 입력값과 ERP 문서번호 기록을 제공한다.

### 15.5 추적성과 정정

- PO부터 생산요청, 문서, ERP와 발신메일까지 주문별 이력을 조회할 수 있다.
- 완료 건은 직접 수정할 수 없고 정정업무로만 변경한다.
- 예외 원인과 담당자 조치결과를 기록한다.
- 실제 수량과 공유 Excel 수동입력에 필요한 값을 화면에 표시한다.

## 16. 구축 순서

1. iCUBE 기술검증과 시범자료 확보
2. PO 업로드, 공통 주문관리, 고객·품목·단위 기준정보
3. 범진전자 일반·분할납품과 국내 문서·메일
4. CHEMTRO VINA QY·QP·선적정보와 해외 문서·메일
5. iCUBE 조회·등록 연계 또는 수동등록 지원
6. 예외, 감사이력, 정정, 백업과 장애복구
7. 1개월 시범운영, 성공지표 검토와 정식 전환 승인

## 17. 의도적으로 수용한 운영위험

- 생산요청을 입력한 영업담당자가 단독 승인한다.
- 업무 예외는 해당 담당자에게만 알리고 다른 역할로 자동 확대하지 않는다.
- BL 원본과 수신메일을 시스템에 저장하지 않아 증빙은 개인 Outlook에서 찾아야 한다.
- 공유 Excel 입력 여부와 정확성을 시스템이 확인할 수 없다.
- 개인 Outlook 수신메일을 자동수집하지 않으므로 QP와 선적정보 입력은 담당자에게 의존한다.

이 위험은 사용자 검증과 확인을 거쳐 1차 시범범위에서 수용한다.
