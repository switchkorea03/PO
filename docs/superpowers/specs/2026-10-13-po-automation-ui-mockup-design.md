# PO 발주·출고 자동화 UI 목업 상세설계

- 작성일: 2026-10-13
- 상태: 사용자 방향 승인, 구현 전
- 기준 설계: `docs/superpowers/specs/2026-10-13-po-order-shipment-automation-validated-design.md`
- 목적: 실제 화면을 구현할 개발자가 레이아웃, 필드, 상태, 행동과 오류 처리를 그대로 참고할 수 있는 클릭형 UI 목업의 기준을 정한다.

## 1. 목표와 범위

내부 영업담당자가 고객 PO 업로드부터 국내 출고 또는 해외 중계무역 선적 완료까지 한 시스템에서 현재 상태와 다음 행동을 명확히 파악하도록 한다. 목업은 실제 ERP, Outlook, OCR, 파일 저장소와 연결하지 않으며 샘플 데이터와 화면 상태 전환만 제공한다.

주요 사용자:

- 영업담당자: PO 검토, 생산요청, 납품·선적정보, 예외 처리
- 구매팀: 국내 출고일정과 전달업무 확인
- 영업관리팀: 전체 진행현황, 완료내역, 기준정보 관리
- 관리자: 사용자 권한, 외부연계와 기준정보 설정

목업 성공 기준:

- 개발자가 화면별 정보와 버튼의 활성조건을 추가 해석 없이 파악할 수 있다.
- 사용자가 정상, 부분출고, 확인 필요와 예외 흐름을 클릭해 확인할 수 있다.
- 국내와 해외 흐름의 공통 골격 및 서로 다른 입력정보가 분명하다.
- 폐기된 수신메일, BL 업로드/OCR, 공유 Excel 자동연동 기능이 화면에 나타나지 않는다.

## 2. 승인된 시각 방향

### 2.1 전체 방향

`균형형 업무 워크벤치`를 사용한다. 고밀도 표만 제공하지 않고, 현재 우선업무·일정·업무상태를 함께 보여준다. 초보 사용자도 다음 행동을 찾을 수 있으면서 숙련 사용자가 반복업무를 빠르게 처리하도록 설계한다.

### 2.2 승인된 핵심 레이아웃

- 대시보드: `B1 우선업무 + 일정`
- 주문 상세: `D1 단계표시 + 작업 사이드바`
- PO 검토: `P1 좌우 연동 비교`

### 2.3 시각 스타일

- 주색: 청록 계열. 내비게이션과 기본 행동에 사용한다.
- 보조색: 파랑은 진행, 녹색은 완료, 주황은 확인 필요, 빨강은 실패·차단, 회색은 비활성 상태다.
- 색상만으로 상태를 구분하지 않고 아이콘과 명확한 한국어 상태문구를 함께 사용한다.
- 카드, 표, 폼을 혼합하되 정보 간 여백과 제목 계층을 일정하게 유지한다.
- 숫자, 수량, 단가와 통화는 표에서 오른쪽 정렬한다.
- 외부쓰기 안전모드를 공통 상단에 항상 표시한다.

## 3. 공통 애플리케이션 골격

### 3.1 좌측 내비게이션

표시 순서:

1. 오늘의 업무
2. PO 관리
3. 국내 출고
4. 해외 선적
5. 생산요청
6. 문서·메일
7. 예외·정정
8. Excel 복사용 값
9. 기준정보 관리

역할별 표시:

- 영업담당자: 본인 업무 중심으로 1~8 표시
- 구매팀: 오늘의 업무, 국내 출고, 문서 조회 표시
- 영업관리팀: 전체 메뉴와 기준정보 표시
- 관리자: 기준정보와 연계설정 표시

### 3.2 상단 바

- 현재 화면 제목과 breadcrumb
- PO 번호·고객사·품목 통합검색
- `ERP 쓰기 비활성/활성` 표시
- `메일 초안 전용/자동발송` 표시
- 내 알림과 미처리 예외 수
- 현재 사용자와 역할

### 3.3 공통 상태와 피드백

| 종류 | 색상 | 표현 | 동작 |
|---|---|---|---|
| 진행 중 | 파랑 | 아이콘 + `진행 중` | 다음 행동을 안내 |
| 완료 | 녹색 | 체크 아이콘 + `완료` | 완료값은 읽기전용 |
| 확인 필요 | 주황 | 경고 아이콘 + 원인 | 담당자 입력 전 후속단계 차단 |
| 처리 실패 | 빨강 | 오류 아이콘 + 실패단계 | 재시도 또는 수동처리 제공 |
| 비활성 | 회색 | 잠금 아이콘 + 조건 | 실행 불가 이유 표시 |

성공 토스트는 짧게 표시하되 외부작업 결과는 화면 이력에도 영구 표시한다. 사용자가 수정한 값, 자동 추출값과 원본값을 구분한다.

## 4. 화면 목록

### 4.1 오늘의 업무 대시보드

상단 요약:

- 내가 처리할 일
- 오늘 출고·선적
- 확인 필요
- 미처리 예외

본문 왼쪽 `우선 처리` 목록:

- PO 번호와 고객사
- 국내·해외 구분
- 필요한 행동
- 기한 또는 예정시간
- 상태 배지
- `열기` 행동

본문 오른쪽 또는 하단 일정:

- 오늘·내일의 출고, 선적, 구매팀 안내, 고객메일 예정
- 기한이 지난 항목은 주황 또는 빨강으로 표시
- 국내·해외와 담당자 필터

### 4.2 PO 목록

필터:

- PO 번호·고객사·품목 검색
- 국내·해외
- 담당자
- 검토 대기, 처리 중, 생산요청 승인 대기, 출고·선적 준비, 부분출고, 완료, 예외, 취소
- 납기기간

표 열:

- 구분, 고객사, PO 번호, 품목, 주문수량, 실제수량, 잔량, 납기일, 현재 단계, 담당자, 예외

기본 정렬은 확인 필요와 납기 임박 순서다. 행을 선택하면 주문 상세로 이동한다.

### 4.3 PO 업로드

- 고객사를 먼저 선택하거나 업로드 후 시스템 제안을 확인한다.
- PDF만 허용한다.
- 드래그앤드롭 영역과 파일선택 버튼을 제공한다.
- 파일명, 크기, 페이지 수와 SHA-256 중복검사 상태를 표시한다.
- 업로드 뒤 추출 중, 추출 완료, 알 수 없는 양식, 파일 오류 상태를 제공한다.

### 4.4 PO 추출 검토

P1 좌우 연동 비교를 사용한다.

왼쪽:

- 원본 PDF 페이지
- 확대·축소, 페이지 이동, 원본 다운로드
- 오른쪽에서 선택한 필드의 원문 위치 강조

오른쪽:

- 고객사명, PO 번호, 주문일
- 품목코드, 품명
- 주문수량과 단위
- 단가와 통화
- 공급가액과 재계산값
- 요청 납기일
- 고객 담당자
- 비고·특별 요청사항
- 해외 주문의 Invoice No., EXW Date, ETD, ETA 상태

각 필드는 원본값, 정규화값, 신뢰도, 사용자 수정 여부를 표시한다. PO 번호·수량·단가·통화의 신뢰도가 낮으면 반드시 확인하게 한다.

하단 고정 행동:

- 임시저장
- 검토완료
- 예외로 전환
- 취소

### 4.5 중복 PO와 수정본 비교

- 같은 고객사·PO 번호·같은 파일내용이면 중복 차단 메시지를 표시한다.
- PO 번호는 같고 내용이 다르면 기존 버전과 수정본을 좌우 비교한다.
- 변경 필드를 색상과 이전값/새값으로 표시한다.
- 이미 출고된 수량은 잠금 처리하고 미출고 잔량만 변경할 수 있다.
- `수정본 승인`, `반려`, `원본 유지` 행동을 제공한다.

### 4.6 공통 주문 상세

D1 단계표시 + 작업 사이드바를 사용한다.

상단 헤더:

- PO 번호, 고객사, 국내·해외, 담당자, 납기일, 현재 상태
- 버전, 수정본 상태와 예외 표시
- 완료 건에는 `정정업무 만들기`만 제공한다.

단계표시:

- 국내: PO 검토 → 재고 확인 → 생산요청 → 출고 준비 → ERP·문서·메일 → 완료
- 해외: PO 검토 → 출고가능 확인 → 생산요청 → QY 발송 → 공장 회신 대기 → QP·선적정보 → ERP·메일 → 완료

본문:

- 주문 요약과 품목
- 선택된 업무유형의 상세영역
- 문서·ERP·메일 처리상태
- 감사 이력

오른쪽 작업 사이드바:

- 현재 단계에서 수행할 핵심 작업 한 개를 우선 표시한다.
- 보조 작업과 수동업무 체크를 아래에 표시한다.
- 선행조건이 충족되지 않으면 버튼을 비활성화하고 이유를 표시한다.

## 5. 국내 업무 화면

### 5.1 재고와 생산요청

- iCUBE `일별재고현황`의 품목코드, 조회시각과 재고값
- 다른 담당자의 미확정 계획이 반영되지 않은 참고값이라는 안내
- 생산요청 수량 직접 입력
- 등록일 +14일 기본 납기일과 수정 기능
- 담당자 단독 승인
- 자동 ERP 등록 또는 수동등록 선택
- 수동등록 시 ERP 문서번호, 문서번호가 없을 때 사유

시스템은 부족수량, FCST 또는 안전재고 수량을 제안하지 않는다.

### 5.2 범진전자 납품회차

표 열:

- 회차
- 예정 납품일·예정수량
- 실제 납품일·실제수량
- 누적 실제수량
- 잔량
- 구매팀 안내상태
- 문서·메일 상태

행동:

- 회차 추가
- 발송 전 일정 수정
- 구매팀 안내메일 초안 생성
- 실제수량 확정
- 완료 회차 정정업무 생성

실제수량 합계가 PO 수량을 넘으면 저장을 차단한다. 구매팀 안내 후 변경하면 사유와 취소·대체 문서 및 변경메일 생성을 요구한다.

## 6. 해외 업무 화면

### 6.1 출고 가능수량과 생산요청

- iCUBE `발주미납현황(수입)` 잔량과 조회시각
- 중국 공장 물리재고와 다르다는 안내
- 필요한 경우 생산요청 수량 직접 입력·단독승인
- 당일 기본 납기일

### 6.2 QY Invoice 생성과 발송

입력과 표시:

- EXW Date
- 운송방식 `VSL` 기본, `AIR` 선택
- 고객사 코드
- 계속 증가하는 순번
- 생성될 QY 번호 미리보기
- Invoice 문서 미리보기
- 중국 공장 등록 수신자와 첨부문서

번호 형식은 기존 기준을 유지한다.

`QY + EXW Date(YYMMDD) + '-' + 연속번호 + 고객사코드 + '(' + 운송방식 + ')'`

예: `QY261013-40CHVN(VSL)`

발송 후 현재 작업은 `중국 공장 회신 확인`으로 바뀐다. 시스템이 메일을 읽거나 회신을 자동감지하지 않는다.

### 6.3 공장 회신과 QP·BL 정보 입력

업무 순서:

1. 담당자가 QY Invoice 선적서류를 중국 공장에 보낸다.
2. 중국 공장이 선적 가능 여부를 확인한다.
3. 확정되면 중국 공장이 QP 번호와 BL 서류가 포함된 자료를 보낸다.
4. 담당자가 개인 Outlook에서 회신과 BL을 확인한다.
5. 담당자가 시스템에 QP No., ON BOARD, ETD, ETA 상태와 실제 선적수량을 입력한다.
6. 시스템이 QY 연결 후보를 제안하고 담당자가 확정한다.

시스템은 BL 파일 업로드를 받지 않고 수신메일이나 BL을 저장·판독하지 않는다.

QP 입력 화면:

- QP 원문 전체
- 파싱한 날짜·순번·고객사코드
- 연결 후보 QY 목록
- 1:1 추천과 다대다 직접선택
- ON BOARD 날짜
- ETD
- ETA 날짜와 `확정/예정/전후`
- 실제 선적수량
- Invoice 대비 수량차이

ON BOARD와 ETD가 다르거나 Invoice와 실제수량이 다르면 주황색 확인 상태가 되고, 담당자 사유·확정 전 후속업무를 차단한다.

### 6.4 해외 후속업무

순서를 화면에 고정한다.

1. 고객 선적안내 메일
2. iCUBE 수입선적등록
3. iCUBE 입고처리
4. 내부 영업관리팀 완료메일

이전 단계가 끝나지 않으면 다음 단계 버튼을 비활성화한다. 수동 ERP 처리도 같은 순서를 사용한다.

## 7. 문서와 발신메일

### 7.1 문서 목록

- 고객별 Excel
- QY Invoice
- 거래명세서 Excel·PDF
- 출고 관련 문서

문서마다 종류, 고객사, 주문, 템플릿 버전, 생성일시, 생성자, 상태, 교체·VOID 관계를 표시한다.

### 7.2 발신메일

지원하는 메일:

- 중국 공장 QY Invoice
- 해외 고객 선적안내
- 국내 출고 전날 구매팀 안내
- 국내 고객 거래명세서
- 내부 영업관리팀 완료 안내

메일 확인창은 수신자, 제목, 본문, 첨부파일, 고객사 일치검사와 중복방지 키를 표시한다. 첫 2주는 기본 버튼을 `Outlook 초안 만들기`로 표시한다. 야간·휴일 자동발송 대기는 예정 발송시간을 보여준다.

## 8. 예외, 정정과 Excel 복사용 화면

### 8.1 예외 작업함

- 예외 유형, 주문, 발생단계, 담당자, 발생일시
- 원인과 영향을 받는 후속작업
- 해결에 필요한 필드
- 수정, 확인, 반려와 재처리

예외는 해당 영업담당자에게만 표시하고 다른 역할로 자동 확대하지 않는다.

### 8.2 정정업무

- 원래 값과 정정 값
- 정정 사유
- 담당자
- 다시 처리할 ERP·문서·메일 선택
- 원본 완료기록 링크

완료기록 자체는 편집할 수 없다.

### 8.3 Excel 복사용 값

표시 필드만 제공한다.

- 담당자
- 거래처
- 모델
- 통화
- 단가
- 실제일
- 최종수량

행 단위 복사와 전체 복사는 제공하지만 Excel 파일 선택, 읽기, 쓰기, 완료표시, 수식·정확성 검사는 제공하지 않는다.

## 9. 기준정보 화면

- 고객사와 담당자
- 국내·해외 구분과 분할납품 허용
- 고객사 코드
- 고객품목과 iCUBE 품목코드 매핑
- 품목별 승인 단위환산
- 금액 반올림과 허용오차
- PO 추출 프로필과 OCR 자동확정 상태
- 문서양식과 버전
- 발신메일 목적별 등록 수신자
- ERP 연계모드와 메일 운영모드

비밀값은 표시하거나 입력받지 않고 연결상태와 재연결 행동만 제공한다.

## 10. 버튼 활성조건

- `검토완료`: 모든 필수필드가 유효하고 필수 확인항목이 확인됨
- `생산요청 승인`: 담당자가 수량을 직접 입력함
- `실제수량 확정`: 실제일·실제수량이 있고 PO 잔량을 초과하지 않음
- `QY 발송 준비`: EXW Date, 고객코드, 운송방식, 수신자와 문서가 유효함
- `QP 연결확정`: 하나 이상의 QY 배분과 선적정보가 유효함
- `고객안내`: 선적 불일치가 없거나 담당자가 사유를 승인함
- `ERP 후속처리`: 앞선 해외 처리단계가 완료됨
- `완료`: 잔량 0, 실제수량 확정, 필수 ERP·문서·메일 완료
- `정정`: 완료 건에서만 사용하고 사유가 필수임

## 11. 반응형과 접근성

- PC 1440px 기준으로 설계하고 1280px에서도 좌우 비교와 작업 사이드바가 유지되게 한다.
- 태블릿에서는 사이드바를 접고 PDF와 폼을 상하로 전환한다.
- 모바일은 조회, 간단 승인, 예외 확인을 우선 지원한다.
- PO 원본 대조, 다대다 QY/QP 연결과 복잡한 정정은 PC 사용을 안내한다.
- 모든 폼 요소에 label을 연결하고 키보드만으로 접근 가능하게 한다.
- 포커스 표시, 오류 요약과 필드별 오류문구를 제공한다.
- 텍스트와 배경은 WCAG AA 대비를 목표로 한다.
- 표는 헤더와 정렬상태를 보조기술에 전달한다.

## 12. 목업 데이터와 상호작용

샘플 시나리오:

- 범진전자 일반납품
- 범진전자 3회 분할납품과 잔량
- CHEMTRO VINA VSL QY 발송 후 공장 회신 대기
- QP 입력과 정상 1:1 연결
- QY/QP 다대다 연결
- ON BOARD/ETD 불일치
- Invoice/실제 선적수량 불일치
- PO 동일파일 중복
- 부분출고 후 수정본
- ERP 수동등록
- Outlook 초안 전용
- 완료 건 정정

목업은 브라우저 로컬상태만 사용하고 새로고침 시 초기화할 수 있다. 실제 파일은 업로드하지 않으며 샘플 PDF 미리보기를 사용한다.

## 15. 검증 기준

- 모든 좌측 메뉴와 주요 행동이 샘플 화면으로 연결된다.
- 국내·해외 정상흐름과 주요 예외흐름을 클릭해 재현할 수 있다.
- B1, D1, P1의 승인된 레이아웃이 일관되게 적용된다.
- 해외 화면은 QY 발송 후 공장 회신을 사람이 확인하고 QP·선적정보를 입력하는 순서를 정확히 보여준다.
- 기존 QY 번호 규칙을 유지한다.
- 폐기 범위가 화면, 버튼, 메뉴 또는 안내문으로 되살아나지 않는다.
- PC, 태블릿과 모바일의 핵심 화면이 깨지지 않는다.
- 버튼의 활성·비활성 이유와 오류문구가 명확하다.
